ETAPA 2 — EXTRAÇÃO E ORDENAÇÃO

2. Ordenação

Com o Max-Heap montado, o maior elemento está sempre na raiz (vetor[0]).

Esse elemento é trocado com o último elemento do vetor ativo, que passa à posição definitiva.
Em seguida, o heap é reconstruído ignorando o fim já ordenado até restar 1 elemento.

CÓDIGO EM C
FUNÇÕES AUXILIARES: trocar() E max_heapify()
void trocar(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

Lógica da dupla em memória

• trocar(): usa ponteiros (*a, *b) para permutar os dois valores direto no vetor.

• max_heapify(): calcula índices dos filhos e valida limites (< tamanho).

• Se um filho for maior que pai, troca e desce recursivamente pela subárvore.

void max_heapify(int vetor[], int tamanho, int pai) {
    int maior = pai;
    int filhoEsquerdo = 2 * pai + 1;
    int filhoDireito  = 2 * pai + 2;

    if (filhoEsquerdo < tamanho &&
        vetor[filhoEsquerdo] > vetor[maior]) {
        maior = filhoEsquerdo;
    }
    if (filhoDireito < tamanho &&
        vetor[filhoDireito] > vetor[maior]) {
        maior = filhoDireito;
    }
    if (maior != pai) {
        trocar(&vetor[pai], &vetor[maior]);
        max_heapify(vetor, tamanho, maior);
    }
}
CÓDIGO EM C
CONSTRUÇÃO E ORDENAÇÃO: build_heap() E heapSort()
void build_heap(int vetor[], int tamanho) {
    for (int i = tamanho / 2 - 1; i >= 0; i--) {
        max_heapify(vetor, tamanho, i);
    }
}

1. build_heap — Bottom-Up em O(n)

Inicia no índice tamanho / 2 - 1, o último nó que possui filhos na árvore binária.

Organiza todas as subárvores de baixo para cima até consolidar o maior elemento na raiz vetor[0].

void heapSort(int vetor[], int tamanho) {
    build_heap(vetor, tamanho);

    for (int i = tamanho - 1; i > 0; i--) {
        trocar(&vetor[0], &vetor[i]);
        max_heapify(vetor, i, 0);
    }
}

2. heapSort — Extração em O(n log n)

Move vetor[0] para o fim e chama max_heapify(vetor, i, 0) — apenas a parte ainda não ordenada (0..i-1) é reorganizada.

Passagem por endereço sem cópia extra

Em trocar(&vetor[0], &vetor[i]), apenas endereços trafegam pela chamada — o algoritmo ordena in-place no mesmo bloco.

2

Verificação de limites contra Segfault

Antes de indexar vetor[filhoEsquerdo] ou vetor[filhoDireito], o if garante filho < tamanho por curto-circuito.

3

Ciclo limpo de memória

Validação imediata v == NULL, liberação com free(v) após cada medição e zeramento do ponteiro (v = NULL).

O algoritmo garante O(n log n) em todos os casos porque build_heap leva O(n)
e cada uma das n − 1 chamadas a max_heapify consome até O(log n).
ESTÁVEL OU
ADAPTATIVO?
Nenhum dos dois!!
Impacto prático: irrelevante ao ordenar inteiros simples, mas restritivo quando chaves secundárias exigem preservar a ordem original.
1

Por que não é estável?

O Heap Sort realiza trocas à distância no vetor (como enviar a raiz para o final), invertendo a ordem relativa de elementos com chaves iguais.

2

Por que não é adaptativo?

Mesmo se o vetor entrar já ordenado ou quase ordenado, o método constrói o Max-Heap do zero e executa as n − 1 extrações, mantendo O(n log n).

Interpretação Esperada dos Dados

Aleatório, Quase Ord. e Ordenado (~41,8–44,2 ms)

Permanecem próximos porque o algoritmo sempre remonta e extrai o Max-Heap do zero, sem aproveitar ordenação prévia.

Ordem Decrescente (~38,4 ms)

Leve vantagem inicial: o vetor já nasce satisfazendo a regra pai ≥ filhos (0 trocas no build_heap), mas a extração segue O(n log n).

Muitas Chaves Duplicadas (~27,6 ms)

Como max_heapify testa estritamente >, quando pai e filhos têm chaves iguais a descida encerra mais cedo.
